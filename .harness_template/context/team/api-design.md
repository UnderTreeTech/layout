## 接口设计规范

接口定义是代码质量的直接反应，优秀的接口望文知义。接口定义遵循以下规范要求
 
- 【强制】相同实体相同参数，全局必须统一字段命名及字段类型 
> 示例:用户详情、编辑用户、用户列表接口中，用户名字段必须统一为username且为string

- 【强制】接口入参、出差都必须为小写，字母间以下划线_相连接
>示例：username、mobile、course_name

- 【强制】接口名及出入差定义必须具有可读性，不能出现拼音
> 
> 正向：username、mobile、course_name
> 
> 反向：kcmc(课程名称)、xingming(姓名)

- 【强制】非复杂接口，入参尽量不要超过10个。入参必须进行基础判断校验及参数类型定义
> 示例：用户名username，基础校验包括空、上下限；用户年龄age，基础校验包括正数、上下限
>
> |参数名         | 参数类型           | 描述     |是否必填| 基础校验|
>|------------|--------------|---------------|-------|--------|
>|username 	|  string   	| 用户姓名  | 是	     | 非空、上下限 |
>|age       | string        | 用户年龄       |是        | 正数、上下限|
> 
> 
>

- 【强制】出参严格控制，前端不需要的不给，不能整个record不经过滤直接输出
> 示例
>
> |参数名         | 参数类型           | 描述     |
>|------------|--------------|---------------|
>|username 	|  string   	| 用户姓名       | 
>|age       | string        | 用户年龄       |
>

- 【强制】出入参均定义为string类型，以最大程序兼容各种编程语言

- 【强制】接口统一返回格式，请求成功code值统一为0，msg统一为ok，data字段必须为对象格式；请求不成功code为非0值，msg展示具体业务错误
>
> ```
>{
>"code" : 0,
>"msg" : "ok",
>"datas" : {}
>}
>```

- 【强制】接口文档wiki以markdown方式书写，简明清晰

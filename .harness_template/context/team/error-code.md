# 错误码规范

## 1. 错误码空间分配

错误码从 `100000` 开始，按业务域分配，每个业务域给 **1000** 个错误码空间。

| 前缀 | 范围 | 业务域 | 说明 |
|-----|------|-------|------|
| `10` | `100000` - `100999` | 公共/基础 | 通用错误（内部错误、参数非法、限流等） |
| `11` | `110000` - `110999` | 用户服务 [已废弃] | 用户注册/登录/会话相关 |
| `12` | `120000` - `120999` | 订单服务 | 订单创建/查询/状态流转相关 |
| `13` | `130000` - `130999` | 支付服务 | 支付/退款/回调相关 |
| `14` | `140000` - `140999` | 预留 | 待分配 |
| `15` | `150000` - `150999` | 预留 | 待分配 |

> **新增错误码前，必须先查本文件确认空间未被占用，再向本文件登记。**
> **新增服务时，通过 `/service:onboard` 或 `/service:harness` 自动预留码段。**

---

## 2. 错误码格式

```go

import "github.com/UnderTreeTech/waterdrop/pkg/status"
// 错误码定义示例
var (
    // 成功
    CodeSuccess = status.New(0, "成功")

    InternalError = status.New(100000, "网络开小差，请稍后重试")
)
```

## 3. 错误响应格式

```json
{
    "code": "110001",
    "msg": "用户不存在",
    "trace_id": "req-xxx-yyy-zzz",
    "datas": {}
}
```

## 5. 规范约束

- **禁止**：直接返回 HTTP 状态码作为业务错误码
- **禁止**：在不同模块中使用相同的错误码值
- **必须**：新增错误码前在本文件登记
- **必须**：错误信息使用中文（面向用户）或英文（面向开发者），不混用
- **必须**：内部错误（100000）不暴露堆栈信息给客户端

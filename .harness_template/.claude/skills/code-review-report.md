# Skill: code-review-report

> **定位**：多维度代码审查报告生成器。
> **触发**：阶段 4.4 编码循环中，由 `code-review-preparer` Agent 收集 diff + 上下文后调用。

---

## 审查维度（8 个，并行执行）

| 维度      | 检查内容 |
|---------|---------|
| **一致性** | 代码风格、命名规范是否符合 `context/team/code-style.md` |
| **度**   | 函数/方法复杂度，单个函数不超过 50 行 |
| **安全**  | 敏感数据处理、SQL 注入、权限校验 |
| **处理**  | 错误处理是否完整，是否使用了正确的错误码 |
| **漏洞**  | 常见 Go 漏洞：goroutine 泄漏、nil 指针、竞态条件 |
| **一致**  | 接口实现是否与 IDL 定义一致 |
| **性能**  | 是否有明显的性能问题（N+1 查询、无限循环、大对象复制） |
| **检查**  | 是否有遗漏的边界条件、空值处理 |

---

## 执行流程

### Step 1: 加载上下文

```
读取 code-review-preparer 提供的：
- git diff 内容
- 涉及的服务信息（来自 .service-matrix/dependencies.yaml）
- 相关的踩坑经验（来自 context/project/*/experience/）
- 团队规范（来自 context/team/）
```

### Step 2: 并行审查

对每个维度独立分析，生成审查意见。

### Step 3: 聚合报告

将 8 个维度的结果聚合为统一报告，写入 `releases/{version}/requirements/{requirement-id}/reviews/{YYYY-MM-DD}-code-review.md`。

---

```markdown

**审查文件**：{文件列表}

|-----|------|-------|
| 一致性 | ✅/⚠️/❌ | {n} |
| 复杂度 | ✅/⚠️/❌ | {n} |

| 错误处理 | ✅/⚠️/❌ | {n} |
| 漏洞 | ✅/⚠️/❌ | {n} |
| IDL 一致性 | ✅/⚠️/❌ | {n} |

## 问题详情

### ❌ 必须修复

{问题列表，每个问题包含：文件、行号、描述、建议修复方案}

### ⚠️ 建议修复

{问题列表}

{建议列表}
```

---

## 状态说明

- ✅ 通过
- ⚠️ 有警告（建议修复，不阻塞）
- ❌ 有错误（必须修复，阻塞合并）

**只有所有维度都是 ✅ 或 ⚠️ 时，才能进入下一步。**

# Skill: service-dependency-analyzer

> **定位**：服务依赖分析器，从 `.service-matrix/dependencies.yaml` 读取服务拓扑，分析影响面。
> **触发**：需求影响面分析阶段，或 `/service:deps` 命令。

---

## 执行流程

### Step 1: 加载服务矩阵

```
读取 .service-matrix/dependencies.yaml
解析服务列表、依赖关系、IDL 冻结字段
```

### Step 2: 识别变更范围

根据需求文档或用户输入，识别：
- 直接变更的服务列表
- 变更类型（新增接口/修改接口/修改逻辑/数据库变更）

### Step 3: 影响面分析

```
对每个直接变更的服务：
1. 查找所有上游服务（调用方）
2. 查找所有下游服务（被调用方）
3. 检查 IDL 变更是否涉及冻结字段
4. 评估影响级别（高/中/低）
```

### Step 4: 生成影响面报告

---

## 输出格式

```markdown
## 📊 影响面分析报告

**直接变更服务**：{service-name}
**变更类型**：{变更类型}

### 上游影响（调用方）

| 服务 | 影响级别 | 说明 |
|-----|---------|------|
| {service-name} | 高/中/低 | {说明} |

### 下游影响（被调用方）

| 服务 | 影响级别 | 说明 |
|-----|---------|------|
| {service-name} | 高/中/低 | {说明} |

### IDL 变更风险

| 字段 | 冻结状态 | 风险说明 |
|-----|---------|---------|
| {field} | 冻结/未冻结 | {说明} |

### 建议

- {建议 1}
- {建议 2}
```

---

## 影响级别定义

| 级别 | 条件 |
|-----|------|
| 高 | 接口签名变更、IDL 冻结字段变更、数据库 schema 变更 |
| 中 | 接口行为变更（非签名）、新增接口、配置变更 |
| 低 | 内部逻辑优化、日志变更、注释变更 |

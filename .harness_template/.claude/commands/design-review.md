# 设计门禁执行命令

## 描述
执行设计阶段门禁检查。

## 触发条件
用户输入 `/design:review`。

## 执行动作
1. 加载当前活动的 requirement id。
2. 调用 `detail-design-quality-reviewer` Agent。
3. 检查 `design.md` 和 `tasks/features.json`。
4. **【核心协议校验】**：校验 `design.md` 中的设计是否与**用户在 `/design:new` 第一步交互中确认的服务归属和通信协议**完全一致。
   - 举例：如果用户只要求提供内部 Service 方法，那么设计中若包含 `.proto` 文件或 gRPC 修改，门禁**必须判定为不通过**并拦截。
5. 校验是否满足设计门禁其他所有条件（方案覆盖度、设计核心要素完整度、数据库变更、任务粒度等）。
   - **【设计要素完整性校验】**：检查 `design.md` 中是否明确包含了**改动服务范围、整体流程、架构方案（含改动代码结构）、性能瓶颈点、风险点**。如果没有，门禁**必须判定为未通过**，并主动进行设计补充（列出初步想法），或者询问用户可以补充哪些点。
   - 举例：如果表结构DDL除主键索引外，还设计了其他索引，门禁**必须判定为不通过**并拦截。设计阶段非主键索引仅做建议。
6. 生成报告并写入 `requirements/{requirement-id}/gate-2-design-review.md`。
7. 输出结果给用户。
